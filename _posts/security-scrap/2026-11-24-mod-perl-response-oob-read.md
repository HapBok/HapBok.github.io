오늘은 mod_perl에서 응답 데이터를 보내는 과정에 생긴 범위 밖 읽기 취약점을 정리했다. 발견자 Satoru Yano는 오늘 X에서 여섯 취약점과 수정 버전을 소개했다. 그중 서버의 메모리 내용이 클라이언트에게 전달될 수 있다고 설명한 **CVE-2026-116799** 한 건에 집중했다.

선정한 X 게시물은 **2026년 11월 24일 08:47 KST**에 올라와 조사 시점 기준 최근 24시간 안에 해당한다. 다만 취약점 공지와 수정 버전은 그보다 먼저 공개됐다. 아래 날짜는 사건 발생일이 아니라 게시·공지·배포 시점을 구분한 것이다.

- **분야:** 웹 서버 · 메모리 안전성 · 정보 노출
- **선정 이유:** 버퍼의 길이와 시작 위치를 검사하는 코드가 서버 내부 데이터와 외부 응답 사이의 경계를 어떻게 지키는지 살펴보기 위해 선정했다.
- **한 줄 요약:** mod_perl의 `$r->write()`가 버퍼 범위 밖의 데이터를 읽어 HTTP 응답으로 보낼 수 있는 CVE-2026-116799가 공개됐으며, 수정 버전은 2.0.14다.
- **X 출처:** 발견자 Satoru Yano의 계정 `@satorunet`(표시 이름 satoru.net), **2026-11-24 08:47 KST**, [개별 게시물](https://x.com/satorunet/status/2125013381828784356).
- **원문 출처:** Apache Perl 프로젝트 Steve Hay, *CVE-2026-116799: Apache Perl: OOB read in $r->write($buf, $len, $offset)*, 메일 작성 시각 **2026-11-22 21:14 UTC → 11-23 06:14 KST**, [oss-security에 게시한 공식 공지](https://www.openwall.com/lists/oss-security/2026/11/23/7).
- **배포 자료:** X에서 연결한 [MetaCPAN의 mod_perl 2.0.14 배포 기록](https://metacpan.org/release/SHAY/mod_perl-2.0.14), 업로드 시각 **2026-11-22 20:40 UTC → 11-23 05:40 KST**. 공식 공지의 발견자 이름과 배포 변경 내역의 기여자 이름·도메인을 함께 대조했다.

## 핵심 내용

- **원래 하는 일:** mod_perl은 Apache에서 Perl을 사용할 수 있게 하는 모듈이다. `$r->write($buffer, $len, $offset)`는 문자열 버퍼의 특정 위치부터 지정한 길이만큼 클라이언트로 보내는 API다. 여기서 `offset`은 시작 위치, `len`은 보낼 바이트 수다. [공식 API 문서](https://metacpan.org/dist/mod_perl/view/docs/api/Apache2/RequestIO.pod#write)
- **무엇이 문제인가:** CVE-2026-116799는 이 API의 범위 밖 읽기(out-of-bounds read) 문제다. 유효한 버퍼 영역을 벗어나 읽은 데이터가 응답에 포함될 수 있어 서버 메모리의 정보 노출로 이어질 수 있다. 공식 공지의 영향 버전은 **1.99_01부터 2.0.13까지**이며, 심각도는 Apache의 **important** 분류다. [공식 공지](https://www.openwall.com/lists/oss-security/2026/11/23/7)
- **수정 버전에서 확인한 검사:** 2.0.14 변경 내역에는 `mpxs_Apache2__RequestRec_write()`의 offset 검사가 기재돼 있다. 수정된 소스는 offset이 음수이거나 버퍼 길이보다 크면 오류로 중단한다. 명시적인 길이가 주어졌을 때에는 `len`이 `버퍼 길이 - offset`을 넘지 않는지도 검사한 뒤 데이터를 보낸다. [변경 내역](https://metacpan.org/dist/mod_perl/changes), [2.0.14 소스](https://metacpan.org/release/SHAY/mod_perl-2.0.14/source/xs/Apache2/RequestIO/Apache2__RequestIO.h)

## 공격과 방어 관점

**공격자 관점에서 중요한 경계는 서버 내부의 메모리와 HTTP 응답 사이에 있다.** 응답에 실려야 하는 것은 프로그램이 지정한 유효한 문자열 영역이다. 범위를 벗어난 메모리까지 읽어 응답에 포함하면, 클라이언트에게 보여 줄 의도가 없던 데이터가 밖으로 나갈 수 있다.

다만 mod_perl이 설치돼 있다는 사실만으로 모든 웹 경로에서 원격 악용이 가능하다고 판단할 수는 없다. 어떤 애플리케이션 코드가 이 API를 호출하는지, 외부 입력이 길이나 시작 위치에 영향을 줄 수 있는지 확인해야 한다. 이는 공개된 API와 수정 코드를 바탕으로 정리한 악용 조건의 해석이며, 실제 웹 서비스에서 검증한 결과는 아니다.

**공식 대응은 mod_perl을 2.0.14로 업데이트하는 것이다.** 운영 환경에서는 mod_perl 패키지 또는 모듈에 수정 사항이 반영됐는지 확인해야 한다. 배포판 패키지를 사용한다면 해당 배포판의 보안 공지와 백포트 여부도 확인할 필요가 있다. 후자는 운영 환경에 적용할 때의 확인 사항이며, Apache 공지가 제시한 수정 버전은 2.0.14다.

수정 코드에서 눈여겨볼 부분은 offset을 부호 있는 값인 상태에서 먼저 검사한다는 점이다. 길이 비교에도 `offset + len`을 더하는 대신 남은 길이에서 빼는 방식을 사용한다. 소스 주석은 부호 변환과 정수 오버플로로 범위 검사가 무력화되는 경우를 피하기 위한 이유를 설명한다. [수정 버전의 검사 코드와 주석](https://metacpan.org/release/SHAY/mod_perl-2.0.14/source/xs/Apache2/RequestIO/Apache2__RequestIO.h)

## 확인 상태

- **확인한 내용:** 취약점과 영향 버전이 공개됐고, mod_perl 2.0.14 배포 기록·변경 내역·수정 소스를 확인했다. X 작성자가 발견자라는 설명은 Apache 공식 공지의 Satoru Yano 크레딧 및 배포 기록의 기여자 정보와 대조했다.
- **미확인:** 확인한 공지와 배포 자료에서는 공개 공격 PoC, 실제 악용·피해 사례, 유출된 데이터의 종류와 규모를 확인하지 못했다. 이번 한 건을 RCE가 확인된 취약점으로 설명하지 않는다.
- **정리 범위:** 공개 자료와 수정 소스를 읽고 정리한 기록이다. 취약 버전에서의 공격 재현이나 패치 전후 실행 검증은 수행하지 않았다. 공식 공지에는 전용 탐지 규칙이나 공격 지표가 제시돼 있지 않다.
