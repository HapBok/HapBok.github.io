1Password의 백엔드 침해사고를 골랐다. 직원 계정 하나가 소스 코드와 배포 권한으로 이어질 때 어떤 피해가 생기는지, 서버가 침해돼도 고객 금고의 암호화 경계가 어떻게 남는지 함께 살펴볼 수 있는 사례다.

**대상일과 블로그 표시일은 2026-11-26이며, 실제 조사·작성·업로드는 2026-11-28에 진행했다.** 아래 표의 기록일도 대상일을 뜻한다. X 게시물은 11월 26일 02:28 KST로 대상일 안에 올라왔다. 회사 공지의 날짜 표기는 11월 25일이며, 조사 시작일은 11월 19일이다. 공지에는 실제 최초 침입 시각이 제시돼 있지 않다.

- **분야:** 침해사고 · 개발 인프라 · 공급망 보안
- **선정 이유:** 계정 접근 권한이 소스 코드·CI/CD·운영 서비스로 확장되는 경로와 피해를 제한한 암호화 경계를 이해하기 위해 선정했다.
- **한 줄 요약:** 1Password는 직원 GitHub 계정 침해 후 공격자가 백엔드에 악성 코드를 배포해 일부 고객 계정 정보를 복사했지만, 고객 금고 내용과 이를 보호하는 키는 영향받지 않았다고 발표했다.
- **X 출처:** 당사자 공식 계정 `@1Password`, **2026-11-26 02:28 KST**, [개별 게시물](https://x.com/1Password/status/2125642686443258030). 공식 블로그 하단의 X 계정 링크와 대조했다.
- **원문 출처:** 1Password, *Update on a security incident involving 1Password’s backend systems*, **2026-11-25 표기**, [공식 사고 공지](https://1password.com/blog/update-on-nov-2026-security-incident). 11월 28일 열람 시점의 내용이며, 초기 게시 이후 문구별 변경 시각은 확인하지 못했다.

## 핵심 내용

- **공격 경로:** 회사는 11월 19일 직원의 회사용 GitHub 계정에 대한 침입 징후를 조사하기 시작했다고 설명한다. 공격자는 비공개 소스와 CI/CD(코드를 빌드하고 배포하는 자동화 시스템)에 접근했고, 백엔드 서비스에 악성 코드를 넣어 고객 관리 데이터를 가져갔다. GitHub 계정이 처음 어떻게 탈취됐는지는 공지에서 확정하지 않았다. [사고 경위](https://1password.com/blog/update-on-nov-2026-security-incident)
- **영향받은 정보:** 일부 고객의 이름·이메일, 계정 및 사용자 식별자, 생성·최근 로그인 시각 등의 기록이 포함됐다. 일부 초대·프로비저닝·복구 이메일 링크의 토큰도 포함됐다고 한다. 회사는 이 토큰만으로는 계정에 접근할 수 없으며, 추가 SSO 로그인 또는 등록 이메일로 보내는 코드가 필요하다고 설명한다. [영향 범위](https://1password.com/blog/update-on-nov-2026-security-incident)
- **회사 측 확인:** 고객 금고 내용·금고 보호 키·계정 복구 키·앱과 브라우저 확장 프로그램은 영향받지 않았다고 밝혔다. 이는 당사자의 조사 결과이며 내가 독립적으로 시스템을 검증한 결과는 아니다. 전체 고객이 피해를 입었다거나 저장된 비밀번호가 유출됐다고 확대해 쓰지 않는다. [공식 설명](https://1password.com/blog/update-on-nov-2026-security-incident)

## 공격과 방어 관점

**공격자 관점에서는 개발자의 계정 권한과 운영 배포 권한이 이어지는 지점이 중요하다.** 저장소를 읽는 권한뿐 아니라 서비스의 동작을 바꿀 수 있는 배포 경로에 접근하면, 정상 서비스가 고객 데이터를 복사하는 수단으로 바뀔 수 있다. 이번 사고에서 회사가 설명한 악성 백엔드 코드 배포가 그 예다.

반대로 서버가 보유한 계정 메타데이터와 고객 금고를 복호화하는 비밀은 구분해야 한다. 1Password는 고객의 계정 비밀번호와 Secret Key를 보관하지 않는 설계 덕분에 금고 내용에 접근할 수 없었다고 설명한다. 내가 주목한 점은 침입 방지와 별개로, 한 시스템의 침해가 곧 모든 비밀의 노출이 되지 않도록 경계를 두는 설계다. [회사 설명](https://1password.com/blog/update-on-nov-2026-security-incident)

**공개된 대응**은 해당 GitHub 계정 비활성화, 탈취 토큰 폐기, 공격자가 만든 접근 제거, 노출 가능성이 있는 내부 자격 증명 교체·폐기, 정상 서비스 복구다. 회사는 GitHub·CI/CD·엔드포인트 통제와 탐지를 강화하고 외부 전문가 검증을 진행한다고 밝혔다. 구체적인 탐지 규칙과 완전한 근본 원인 분석은 아직 공개되지 않았다.

고객에게는 계정 변경 작업이 필요하지 않다고 안내하면서도, 예상하지 못한 초대·복구 요청 등 피싱에 주의하라고 권고한다. 공개된 이메일 주소가 후속 사회공학에 쓰일 가능성은 고려할 수 있지만, 이 사고 정보가 실제 후속 피싱에 사용됐다는 증거를 이번 조사에서 확인한 것은 아니다. [회사 대응과 고객 안내](https://1password.com/blog/update-on-nov-2026-security-incident)

## 확인 상태

- **상태:** 실제 침해와 일부 계정 정보 복사에 대한 당사자 발표. 상세 근본 원인 분석은 조사 완료 후 공개 예정이라고 한다.
- **미확인:** 최초 계정 탈취 수단, 정확한 피해 고객 수, 공격자의 신원, 전체 공격 시계열, 외부 검증의 최종 결과.
- **정리 범위:** X와 공식 공지 열람. 악성 코드 분석·공격 재현·회사 내부 시스템 검증은 수행하지 않았다. 특정 CVE나 공개 PoC로 설명하는 사건도 아니다.
